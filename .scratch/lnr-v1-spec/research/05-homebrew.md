# Research: How does `lnr` reach a Mac?

Resolves `.scratch/lnr-v1-spec/issues/05-homebrew-distribution.md`.

Researched 2026-09-08. Primary sources: GoReleaser docs + repo, `docs.brew.sh` + `Homebrew/brew`
source, and direct experiment on this machine (macOS Tahoe arm64, Homebrew 6.0.22, Go 1.27.1).

## Headline

Three findings invert the "obvious" answer, and two of them are the ones the ticket warned were
easy to get wrong:

1. **`brews:` (Homebrew *formula*) is fully deprecated in GoReleaser as of v2.16.** The supported
   way to ship a prebuilt Go binary through Homebrew is now `homebrew_casks:`.
2. **That deprecation flips the Gatekeeper answer.** Formula installs were never quarantined;
   cask installs *are*. An unsigned binary shipped as a cask **is SIGKILLed on first run** unless
   you strip the quarantine bit. Verified empirically below (exit code 137).
3. **homebrew-core is not plausible for `lnr`.** Self-submission by the repo owner requires
   **90 forks / 90 watchers / 225 stars**, and a repo under 30 days old is ineligible outright.

Net recommendation: personal tap (`taciogt/homebrew-tap`) + `homebrew_casks` + the
`xattr` post-install hook. No Apple Developer account, no notarization, no paid anything.

## 1. Minimal goreleaser + personal tap setup

### 1.1 The `brews` → `homebrew_casks` migration is mandatory

> "The legacy `brews` configuration in GoReleaser, used for generating Homebrew formulas that
> installed pre-compiled binaries, is now fully deprecated. Users should migrate to
> `homebrew_casks`, which is the recommended method for distributing pre-compiled binaries with
> Homebrew."
>
> — [GoReleaser v2.16 announcement](https://github.com/goreleaser/goreleaser/blob/main/www/content/blog/goreleaser-v2.16.md)

`homebrew_casks` was introduced in **GoReleaser v2.10**
([docs](https://goreleaser.com/customization/homebrew_casks/)). Since `lnr` is greenfield, there is
nothing to migrate — just never write a `brews:` block.

This matters beyond style: most blog posts and templates you will find for "Go CLI + Homebrew +
goreleaser" predate v2.16 and will hand you a `brews:` block. Those are stale.

### 1.2 What GoReleaser actually generates

Primary evidence — GoReleaser's own generated cask, from
[`goreleaser/homebrew-tap@master:Casks/goreleaser.rb`](https://github.com/goreleaser/homebrew-tap/blob/master/Casks/goreleaser.rb)
(v2.18.1 at time of reading):

```ruby
# This file was generated by GoReleaser. DO NOT EDIT.
cask "goreleaser" do
  version "2.18.1"

  on_macos do
    on_arm do
      sha256 "8e912c5c…"
      url "https://github.com/goreleaser/goreleaser/releases/download/v#{version}/goreleaser_Darwin_arm64.tar.gz"
    end
    on_intel do
      sha256 "623e9ba5…"
      url "https://github.com/goreleaser/goreleaser/releases/download/v#{version}/goreleaser_Darwin_x86_64.tar.gz"
    end
  end
  on_linux do
    on_arm do  … end
    on_intel do … end
  end

  name "goreleaser"
  desc "Release engineering, simplified"
  homepage "https://goreleaser.com"

  livecheck do
    skip "Auto-generated on release."
  end

  binary "goreleaser"
  manpage "manpages/goreleaser.1.gz"
  bash_completion "completions/goreleaser.bash"
  # …
end
```

**One cask file covers every OS/arch** via `on_macos`/`on_linux` + `on_arm`/`on_intel` blocks. You
do not write per-arch files, and you do not need a universal binary (see §4).

### 1.3 Copy-pasteable `.goreleaser.yaml`

Starting point for `lnr`. Per the map's "planning only" constraint this lives here as a spec
artifact, not as a real file at repo root.

```yaml
# .goreleaser.yaml
version: 2

project_name: lnr

before:
  hooks:
    - go mod tidy

builds:
  - id: lnr
    main: ./cmd/lnr          # adjust to actual main package path
    binary: lnr
    env:
      - CGO_ENABLED=0        # keeps the binary static and cross-compilable
    goos:
      - darwin
      - linux                # cheap; drop if you want strictly Mac-only
    goarch:
      - amd64
      - arm64
    ldflags:
      - -s -w
      - -X main.version={{ .Version }}
      - -X main.commit={{ .Commit }}
      - -X main.date={{ .CommitDate }}
    mod_timestamp: "{{ .CommitTimestamp }}"

archives:
  - id: lnr
    ids:
      - lnr
    formats: [tar.gz]
    # Produces e.g. lnr_Darwin_arm64.tar.gz — matches the cask URLs above.
    name_template: >-
      {{ .ProjectName }}_
      {{- title .Os }}_
      {{- if eq .Arch "amd64" }}x86_64
      {{- else }}{{ .Arch }}{{ end }}

checksum:
  name_template: "checksums.txt"

changelog:
  use: github
  sort: asc
  filters:
    exclude:
      - "^docs:"
      - "^test:"
      - "^chore:"

release:
  github:
    owner: taciogt
    name: lnr
  draft: false
  prerelease: auto

homebrew_casks:
  - name: lnr
    ids:
      - lnr
    binaries:
      - lnr
    directory: Casks
    homepage: "https://github.com/taciogt/lnr"
    description: "Linear CLI for agent-driven workflows"
    conflicts: []

    repository:
      owner: taciogt
      name: homebrew-tap
      branch: main
      # Default GITHUB_TOKEN cannot push to another repo — see §5.
      token: "{{ .Env.HOMEBREW_TAP_TOKEN }}"

    # Helps `brew audit` pass when homepage domain != download domain.
    url:
      verified: github.com/taciogt/lnr

    commit_author:
      name: goreleaserbot
      email: goreleaserbot@theuselessweb.com

    # REQUIRED because the binary is neither signed nor notarized. See §3.
    hooks:
      post:
        install: |
          if OS.mac?
            system_command "/usr/bin/xattr",
                           args: ["-dr", "com.apple.quarantine", "#{staged_path}/lnr"]
          end
```

Notes on specific keys:

- `binaries:` — executable names inside the archive; defaults to the cask name.
- `directory: Casks` — where in the tap repo the `.rb` lands. `Casks` is the default and the
  convention Homebrew expects.
- `url.verified` — silences a `brew audit` warning; harmless to include.
- `skip_upload: auto` is worth considering if you want prereleases (`v1.0.0-rc1`) to build
  artifacts without republishing the cask.
- `generate_completions_from_executable:` (GoReleaser **v2.15+**) can emit shell completions by
  running the binary at install time — relevant later given the map's "CLI is the source of truth
  for its own documentation" preference. Not needed for v1.
  ([docs](https://goreleaser.com/customization/homebrew_casks/))

### 1.4 End-to-end release workflow

One-time setup:

1. Create public repo `taciogt/lnr`.
2. Create public repo **`taciogt/homebrew-tap`** — the `homebrew-` prefix is what makes
   `taciogt/tap` a valid tap name. An empty repo with a README is enough; GoReleaser creates
   `Casks/` on first release.
3. Create a fine-grained PAT scoped to `taciogt/homebrew-tap` with **Contents: read and write**.
   Store it as secret `HOMEBREW_TAP_TOKEN` on `taciogt/lnr`.
4. Commit `.goreleaser.yaml` and `.github/workflows/release.yml` (§5).

Each release:

1. `git tag -a v0.1.0 -m "v0.1.0" && git push origin v0.1.0`
2. GitHub Actions fires on the tag; GoReleaser cross-compiles all four OS/arch pairs, builds
   archives + `checksums.txt`, creates the GitHub Release and uploads assets.
3. GoReleaser renders `Casks/lnr.rb` with the real SHA-256s and commits it to
   `taciogt/homebrew-tap` using `HOMEBREW_TAP_TOKEN`.
4. User runs `brew install taciogt/tap/lnr`.

Local dry run before ever tagging: `goreleaser release --snapshot --clean --skip=publish`.

## 2. Personal tap vs. homebrew-core

### 2.1 homebrew-core's current criteria

The criteria were reorganised: notability now lives in a **shared** policy doc that applies to both
homebrew-core and homebrew-cask.

From [`Package-Acceptance-Policy.md`](https://docs.brew.sh/Package-Acceptance-Policy)
(`last_review_date: 2026-07-18`), verbatim:

> ## Notability
>
> A new package must demonstrate public interest beyond its author.
> A GitHub project normally satisfies this requirement by meeting one of these thresholds:
>
> * at least 30 forks, 30 watchers or 75 stars.
> * **at least 90 forks, 90 watchers or 225 stars for a self-submission by the repository owner.**
>
> […] A code repository less than 30 days old is normally not eligible.

From [`Acceptable-Formulae.md`](https://docs.brew.sh/Acceptable-Formulae) (same review date):

> **Stable releases** — Upstream must identify the packaged version as stable and provide an
> immutable tag or release. […] Software without a stable release is difficult to reproduce, bottle
> and support and is not eligible for `homebrew/core`.

> **Versioned and verifiable sources** — An install step must not fetch code from a moving default
> branch or an unversioned, unchecksummed archive.

> **Source availability and licences** — It must either build from source or install portable,
> platform-independent output such as Java bytecode. Proprietary or platform-specific binary-only
> software belongs in a cask.

> **Self-updating software** — Self-update behaviour must be disabled when this can be done without
> a fragile or invasive patch.

Also relevant: *"New submissions may be held to a higher standard than existing packages because
accepting a package creates an ongoing maintenance commitment."*

### 2.2 Is `lnr` plausibly eligible? No.

- **Notability: fails, and by the harder bar.** Taciogt submitting his own tool is explicitly a
  "self-submission by the repository owner" → **90 forks / 90 watchers / 225 stars**. A brand-new
  personal CLI has none of these.
- **Age: fails.** Under 30 days old is "normally not eligible".
- Build-from-source and no-HEAD-only would eventually be satisfiable (homebrew-core builds Go
  formulae from source with `go build`; it would *not* consume the GoReleaser binaries) — but they
  are moot while notability fails.
- Note for later: the map lists "whether the binary self-checks for new versions" as undecided.
  If `lnr` ever self-updates, that is an additional homebrew-core blocker. A tap doesn't care.

**Conclusion: a personal tap is not merely the safe answer, it is the only available one.**
Revisit homebrew-core only if `lnr` ever crosses 225 stars.

### 2.3 What the tap costs in install ergonomics

Short answer: **almost nothing**. One command, no prior `brew tap`:

```
brew install taciogt/tap/lnr
```

Three details, all verified:

- **No separate `brew tap` step.** `brew install` auto-installs the tap. From
  `/opt/homebrew/Library/Homebrew/cmd/install.rb` (Homebrew 6.0.22):
  ```ruby
  elsif (tap_with_token = Tap.with_cask_token(name))
    tap, = tap_with_token
  end
  tap&.ensure_installed!
  ```
- **No `--cask` flag needed.** The same code resolves cask tokens from taps. Verified on this
  machine: `brew info homebrew/cask/ghostty` (fully qualified, no `--cask`) resolves the cask
  identically to `brew info --cask ghostty`.
- **No trust prompt** — despite Homebrew 6.0 adding tap trust. From
  [`Tap-Trust`](https://docs.brew.sh/Tap-Trust): *"Non-official taps require explicit trust by
  default since Homebrew 6.0.0"*, but *"Installing a fully qualified formula or cask name trusts
  only that item."* Confirmed in source — `install.rb` calls
  `Homebrew::Trust.trust_fully_qualified_items!(args.named, …)`.
  `HOMEBREW_REQUIRE_TAP_TRUST=1` is now deprecated because it only requests the default.

  ⚠️ Ergonomic consequence: the **fully-qualified** form is required. Telling users
  `brew tap taciogt/tap && brew install lnr` would hit the trust gate on Homebrew ≥ 6.0. Document
  the one-liner form only.

Real costs of a tap, such as they are: no bottles (users download your release archive rather than
a Homebrew-built bottle — irrelevant for a static Go binary), no `brew search` discoverability, and
no Homebrew endorsement (*"Distribution through a third-party tap does not imply Homebrew
endorsement or support."*).

## 3. Gatekeeper — the part that is easy to get wrong

### 3.1 Formula and cask behave *oppositely*

This is the crux, and the `brews` deprecation is what makes it bite.

- **Formula install: no quarantine.** Homebrew fetches with curl, which does not set
  `com.apple.quarantine`. This is why unsigned Go CLIs installed via `brew install` have
  historically never prompted Gatekeeper.
- **Cask install: quarantine is actively applied.** Homebrew has a whole `Cask::Quarantine`
  subsystem and a `brew doctor` check (`check_cask_quarantine_support`) that warns when it *cannot*
  set the xattr — it is deliberate, not incidental.

Verified on this machine (Homebrew 6.0.22, macOS Tahoe arm64):

```
$ xattr -l /opt/homebrew/bin/aws-vault      # formula-installed
com.apple.provenance:

$ xattr -l /opt/homebrew/Caskroom/ghostty/1.3.1/Ghostty.app   # cask-installed
com.apple.macl:
com.apple.provenance:
com.apple.quarantine: 03c1;6a2dc017;;4ECEB364-3E6E-43F0-A9F1-00D12230725D
```

Formula binaries carry only `com.apple.provenance` (a benign macOS-set attribute, not a Gatekeeper
gate). Cask artifacts carry `com.apple.quarantine`.

### 3.2 Actual first-run experience — measured, not recalled

Do you need signing/notarization? **Strictly, no.** But without the `xattr` hook the binary does
not run at all.

Experiment: build a Go binary exactly as GoReleaser would, apply a quarantine xattr as a cask
install does, and execute it.

```
$ go version
go version go1.27.1 darwin/arm64

$ GOOS=darwin GOARCH=arm64 go build -o qtest main.go
$ codesign -dv qtest
CodeDirectory v=20400 … flags=0x20002(adhoc,linker-signed)
Signature=adhoc
TeamIdentifier=not set

$ ./qtest
hello from lnr                      # runs fine, no quarantine

$ xattr -w com.apple.quarantine "0081;68a00000;Safari;" qtest_q
$ ./qtest_q
                                    # no output
EXIT CODE=137                       # 128 + 9 = SIGKILL

$ xattr -dr com.apple.quarantine qtest_q      # <- exactly what the goreleaser hook runs
$ ./qtest_q
hello from lnr
rc=0
```

**So the precise answer to "what is the first-run UX":**

- **Cask without the hook:** the process is **killed by the kernel — SIGKILL, exit 137**. From an
  interactive shell the user sees `zsh: killed  lnr`. There is no "allow anyway" button in the
  terminal path, and no useful error message. GoReleaser's docs describe the GUI-facing form of the
  same failure: *"users will see the infamous 'App Name is damaged and cannot be opened' alert"* and
  *"Not following this might lead to your app or binary not running."*
  ([docs](https://goreleaser.com/customization/homebrew_casks/))
- **Cask with the hook:** clean. Binary runs on first invocation, no prompt, no dialog, no
  right-click-Open dance. Indistinguishable from a formula install.

Note that the Go toolchain already ad-hoc/linker-signs darwin binaries (`Signature=adhoc`,
`TeamIdentifier=not set`). Ad-hoc signing satisfies arm64's "must have *some* signature" execution
requirement — it does **not** satisfy Gatekeeper, which is why quarantine still kills it.

### 3.3 Caveats on the xattr approach

GoReleaser flags these itself and they should be recorded as accepted risk:

> Use of `xattr` to bypass Gatekeeper circumvents macOS security protections designed to verify
> software authenticity. […] **Apple may disable this bypass method in future macOS versions
> without notice**, potentially breaking software distribution that relies on it.

Proper signing + notarization (GoReleaser supports it via `sign`/`notarize`) requires an Apple
Developer Program membership at a yearly fee. For a personal CLI, the hook is the right trade;
just know the escape hatch exists if Apple closes this door.

`unknown`: whether any currently-shipping macOS version already restricts `xattr -dr` for
non-admin users. Not reproduced here — the strip worked without elevation on macOS Tahoe.

## 4. Cross-compilation: arm64 vs amd64

**What GoReleaser produces** with the config in §1.3 — four archives plus a checksums file:

```
lnr_Darwin_arm64.tar.gz     lnr_Linux_arm64.tar.gz
lnr_Darwin_x86_64.tar.gz    lnr_Linux_x86_64.tar.gz
checksums.txt
```

Pure-Go with `CGO_ENABLED=0` cross-compiles from the `ubuntu-latest` runner with no toolchain
setup, no Docker, no macOS runner. Confirmed locally: `GOOS=darwin GOARCH=amd64 go build` works
from an arm64 Mac.

**Does the formula need both?** It needs both *archives*, but only **one cask file** — GoReleaser
emits `on_arm` / `on_intel` blocks inside a single `Casks/lnr.rb` (see the real example in §1.2).
Homebrew picks the right URL and SHA-256 at install time. Nothing extra to configure.

**Universal binary? Not recommended.** `universal_binaries:` exists
([docs](https://goreleaser.com/customization/builds/universalbinaries/)) but buys nothing here: the
cask already selects by arch, so a universal binary just doubles the download for every user.

I did test the common objection — that `lipo`-merging invalidates the Go linker's ad-hoc signature:

```
$ lipo -create -output qtest_uni qtest_amd64 qtest_arm64
$ codesign -dv qtest_uni
Format=Mach-O universal (x86_64 arm64)
CodeDirectory … flags=0x20002(adhoc,linker-signed)
Signature=adhoc
$ ./qtest_uni
hello from lnr    # rc=0
```

The signature survives and the universal binary runs (Go 1.27.1, macOS Tahoe). So it *would* work —
it is simply unnecessary. Recommendation: two separate darwin archives.

**On Intel support specifically:** keep `darwin/amd64`. It costs one extra archive and zero build
complexity, and it covers pre-2020 Macs. Drop it only if you want to be deliberate about it.

**On Linux (the map's "cheap later" note):** casks do **not** foreclose Linux. Homebrew 6.0.22 ships
`extend/os/linux/cask/installer.rb`, which allows a cask on Linux when it declares `on_linux`, and
`extend/os/linux/cask/quarantine.rb` hardcodes `available? = false` (no quarantine on Linux —
which is why the hook is guarded with `if OS.mac?`). GoReleaser emits `on_linux` blocks
automatically, as its own cask shows. Keeping `goos: [darwin, linux]` costs nothing today.

## 5. GitHub Actions pipeline: secrets and permissions

### 5.1 The one non-obvious requirement

The default `GITHUB_TOKEN` **cannot** push the cask to a second repo:

> "The default GITHUB_TOKEN is limited to the repository containing the workflow. If you need to
> push to a different repository, such as a separate Homebrew tap, you must create a Personal
> Access Token with repo permissions and store it as a repository secret."
>
> — [GoReleaser GitHub Actions docs](https://goreleaser.com/customization/ci/actions/)

And from the cask docs: *"To publish a cask from one repository to another using GitHub Actions,
you cannot use the default action token."* Symptom if you get it wrong:
`resource not accessible by integration`.

### 5.2 Workflow

```yaml
# .github/workflows/release.yml
name: release

on:
  push:
    tags:
      - "v*"

permissions:
  contents: write        # create the GitHub Release on taciogt/lnr

jobs:
  goreleaser:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v7
        with:
          fetch-depth: 0        # REQUIRED: goreleaser needs full history for the changelog

      - name: Set up Go
        uses: actions/setup-go@v7
        with:
          go-version: stable

      - name: Run GoReleaser
        uses: goreleaser/goreleaser-action@v7
        with:
          distribution: goreleaser
          version: "~> v2"
          args: release --clean
        env:
          # Creates the release on this repo.
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          # Pushes Casks/lnr.rb to taciogt/homebrew-tap.
          HOMEBREW_TAP_TOKEN: ${{ secrets.HOMEBREW_TAP_TOKEN }}
```

This pairs with `repository.token: "{{ .Env.HOMEBREW_TAP_TOKEN }}"` in §1.3. (The GoReleaser docs
show the alternative of overriding `GITHUB_TOKEN` wholesale with the PAT; using a separate env var
is preferable — it keeps the release-creation token minimally scoped.)

### 5.3 Checklist

**Secrets on `taciogt/lnr`:**

| Secret | Value | Why |
|---|---|---|
| `GITHUB_TOKEN` | automatic, don't create | Creates the release, uploads assets |
| `HOMEBREW_TAP_TOKEN` | fine-grained PAT, repo-scoped to `taciogt/homebrew-tap`, **Contents: read & write** | Commits the cask to the tap |

**Permissions:** `contents: write` only. GoReleaser's docs show
`packages: write` / `issues: write` / `id-token: write` as commented-out extras — those are for
Docker publishing, milestone closing, and cosign keyless signing respectively. `lnr` needs none.

**Explicitly NOT needed** (half the value of this question):

- ❌ Apple Developer ID certificate, `APPLE_*` secrets, notarization credentials — §3 covers this.
- ❌ `GORELEASER_KEY` — GoReleaser Pro only. Everything in §1.3 is in the free distribution.
  (Pro-only features to avoid: `alternative_names` for versioned casks, `app:` for DMGs.)
- ❌ GPG signing key — optional artifact signing, not required by Homebrew for a tap.
- ❌ A macOS runner — `ubuntu-latest` cross-compiles everything.
- ❌ `brew tap` in CI, or any Homebrew installation on the runner.

## Open / unknown

- `unknown` — whether `xattr -dr com.apple.quarantine` will keep working on future macOS. Apple may
  close it "without notice" per GoReleaser's own warning. Mitigation if it closes: pay for an Apple
  Developer account and enable GoReleaser's `notarize`.
- `unknown` — whether any shipping macOS version restricts `xattr -dr` for non-admin users. Not
  reproduced here.
- Not researched (out of scope for this ticket, flagged in the map as undecided): semver policy,
  update-available notification, and whether `lnr` self-checks for new versions. Note that a
  self-updating binary would be an extra homebrew-core blocker but is fine in a tap.
